# בוט פיוצ'רס דמו — Binance USDT-M (נייר בלבד)

חשבון דמו של **10,000 USDT** שמדמה חוזה USDT-M של Binance: עמלות VIP0 (מייקר 0.02% / טייקר 0.05%), החלקה, מימון אמיתי בזמני המימון, מדרגות מינוף, מרג'ין מבודד, חיסול לפי מחיר מארק, וסטופ/יעד. **אין מפתחות API ואין פקודות אמיתיות.**

הדשבורד הוא לשונית בבית הבוט: `house.html?tab=futures` («בוט פיוצ'רס · Binance דמו»). אין שרת שרץ כל הזמן — מחזור אחד של GitHub Actions כל 15 דקות.

## איך זה רץ

`.github/workflows/binance-paper-desk.yml`

- תזמון `3,18,33,48 * * * *` (כ־3 דקות אחרי סגירת נר 15 דקות) וגם `workflow_dispatch`.
- טוען את `binance-paper/state.json` מענף `pm-desk-data` (אותו ענף של שאר הדסקים).
- משלים את הזמן מאז המחזור הקודם: נרות 1m סגורים לבדיקת סטופ / חיסול, היסטוריית מימון אמיתית, ואז האסטרטגיה על כל נר 1h שנסגר (האות עצמו מנר 4h סגור).
- כותב את אותו קובץ JSON (הון, יתרה, פוזיציות, עסקאות, עמלות, מימון, אחוז הצלחה, ירידה, עקומת הון, אותות, מחירים, יקום, **ומקור המחיר**) ודוחף עם `[skip ci]`.
- מעבר אסטרטגיה לא מריץ היסטוריה כעסקאות ולא מאפס את החשבון. הוא מעריך רק את נר ה־1h הסגור האחרון, ואחר כך שומר את הסטופ על הדקות שאחריו. השבתה אחר כך כן מושלמת, כולל כניסות 1h שהוחמצו.
- סטופ, יעד וחיסול כבר רצים על high/low של נרות 1m שנסגרו מאז `last_1m_open` (ועל מארק לדקת החיסול). אין צורך במחזור תכוף יותר בשביל זה.
- הלשונית עצמה מתעדכנת כל שבריר שנייה בדפדפן: שידור Binance (market, ואז public, ואז הכתובת הישנה), ואם הוא נופל — OKX, ואז REST כל 2.5 שנ׳. מצב החשבון נקרא מחדש כל 45 שנ׳ מ-API של GitHub (ואם הוא חסום, מ-raw). השווי החי = ארנק + רווח פתוח לפי המארק. זה לא פותח עסקאות.

מקור מחיר, לפי הסדר:

1. `https://fapi.binance.com`
2. `https://www.binance.com/fapi` (אותם נתוני production; `fapi.binance.com` מחזיר HTTP 451 מהרבה רצים)
3. נרות ומימון של OKX USDT-SWAP, אם שניהם חסומים — אותו מקור ששאר הדסקים כבר משתמשים בו

עמלות, `tickSize` / `stepSize` / `minNotional` ומדרגות המינוף נשארים של Binance. אם הבורסה חסומה, נטען `data/market_meta.json` שנשמר בריפו. הלשונית כותבת במפורש איזה מקור שימש באותו מחזור.

## אסטרטגיה

פעיל: `ema_trend_4h`. על כל סגירת נר 1h, אם נר ה־4h נסגר באותו רגע, נכנסים רק בחצייה טרייה של EMA20 מעל/מתחת EMA150. סטופ 3×ATR(20) על 4h, בלי יעד (יציאה בסטופ או כשההצלבה מתהפכת). לונג רק מעל EMA50 היומי של המטבע, שורט רק מתחתיו. מינוף 3. סיכון 1%, עד 3 פוזיציות, מרג'ין לעסקה עד 30% מההון, הפסד יומי 5% עוצר כניסות. `trend_ema` ו־`bollinger_mr` נשארים בקוד ולא פעילים.

היקום אינו חמישה מטבעות קבועים. בכל חודש UTC נבחרים 20 חוזי USDT-M במצב TRADING, רשומים כ־12 חודשים לפחות, בלי מטבעות יציבים ובלי זהב (PAXG). הדירוג הוא חציון נפח quote יומי ב־90 הימים האחרונים. החלקה: 1bp מעל $500M ליום, 2bp מעל $100M, 3bp מעל $30M, אחרת 5bp. הרשימה ותאריך הדירוג נשמרים ב־`state.universe`. מטבע בלי נתונים במקור הגיבוי מדולג.

בקטסט של הכלל הזה (נשמר גם ב־`state.strategy.backtest`): מחוץ למדגם ינואר–אוקטובר 2026 +43.4%, הצלחה 36.7%, PF 3.57, ירידה מקסימלית −11.6%, 30 עסקאות. בתוך המדגם ספטמבר 2024–דצמבר 2025 +107.2%, 27.9%, PF 3.07, ירידה −17.8%, 61 עסקאות. זה דמו, לא אישור שהקצה חי.

## מבנה

```
binance-paper-bot/
├── config.yaml                 # סימבולים, עמלות, סיכון, אסטרטגיה
├── data/market_meta.json       # exchangeInfo + מדרגות מינוף (מטמון Binance)
├── bot/
│   ├── execution/paper.py      # הסימולציה (לא שונתה)
│   ├── engine.py, risk.py, margin.py, strategies/
│   ├── feed.py                 # Binance ואז OKX
│   ├── replay.py               # השלמה על נרות סגורים
│   └── desk.py                 # מחזור אחד: טען מצב, השלם, שמור JSON
└── tests/                      # עמלות, מימון, חיסול, PnL, מקור מחיר, השלמה
```

`tunnel.py`, `manage.sh`, `status.py`, דשבורד ה-FastAPI המקומי ולולאת ה-websocket (`live.py`) לא הועתקו — אין מכונה שרצה ברצף. מודל המילוי זהה.

## בדיקות

```bash
cd binance-paper-bot && python -m pytest -q tests
```

הסוויטה גם רצה מתוך `scripts/run-tests.sh`.

## אחרי מיזוג

1. ה-workflow נכנס ל-main ורץ לבד. אם GitHub לא מפעיל workflow חדש עד הרצה ידנית: Actions → binance-paper-desk → Run workflow.
2. דף הבית נבנה מחדש אוטומטית כי `trading-app/**` השתנה (`deploy-trading-app.yml`). הלשונית: `https://aliexpressgood585.github.io/spacehub/house.html?tab=futures`
3. אין סודות להגדיר. הענף `pm-desk-data` כבר קיים.
