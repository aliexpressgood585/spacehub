# daybot — בוט מסחר תוך-יומי ל-Binance USDⓈ-M Futures

בוט Python שרץ 24/7 על שרת. הוא סוחר בטווחים של 1m עד 1h לפי הכללים המדויקים של האפיון: סטאפים S1–S6, פילטרים F1–F7, חוק העלויות וניהול סיכונים קשיח.
**ברירת המחדל היא Testnet.** הבטיחות קודמת לרווח: בכל מקום שיש ספק, הבוט לא סוחר.

> ## ⚠️ השורה התחתונה — לקרוא לפני הכל
> הבקטסט (שנתיים, 7 מטבעות, עמלות, החלקה ו-Funding אמיתיים) מראה ש**אף סטאפ לא עובר את סף האישור** (PF > 1.3 מחוץ למדגם, לפחות 300 עסקאות).
> כל ששת הסטאפים יצאו שליליים או עם מעט מדי עסקאות. לכן `backtest.py` כיבה אותם אוטומטית ב-`config.yaml`.
> **במצב הנוכחי הבוט עולה, מנטר, שולח התראות ולא פותח עסקאות.** זה בדיוק מה שכלל 3 בחלק ו' דורש.
> הדוח המלא נמצא ב-`reports/backtest_report.md`, וההסבר בסעיף 8.

## 2. התקנה מקומית (לבדיקה)

```bash
cd daybot
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # ולמלא (סעיפים 3–4)
python -m pytest -q tests     # 34 בדיקות צריכות לעבור
```

## 3. מפתחות API ב-Testnet

1. נכנסים ל-https://testnet.binancefuture.com ומתחברים (חשבון Testnet נפרד מהחשבון האמיתי).
2. בתחתית המסך, בלשונית **API Key**, יוצרים מפתח ומעתיקים את ה-Key וה-Secret.
3. ב-`.env` מכניסים `BINANCE_API_KEY=...` ו-`BINANCE_API_SECRET=...`.
4. ב-`config.yaml` צריך להיות `mode: testnet` (זו ברירת המחדל).

חלופה: **Demo Trading** של בינאנס (מהאתר הרגיל), `mode: demo` עם מפתחות ה-Demo.
**לעולם לא** שמים מפתחות בקוד או ב-config, ולא שולחים אותם בצ'אט.

## 4. בוט טלגרם

1. בטלגרם פותחים את **@BotFather**, שולחים `/newbot` ומקבלים token.
2. שולחים לבוט החדש הודעה כלשהי.
3. פותחים בדפדפן `https://api.telegram.org/bot<TOKEN>/getUpdates` ומעתיקים את `chat.id`.
4. ב-`.env`: `TELEGRAM_BOT_TOKEN=...` ו-`TELEGRAM_CHAT_ID=...`.

הבוט מקבל פקודות **רק** מה-chat id הזה.

| פקודה | מה היא עושה |
|---|---|
| `/status` | הון, פוזיציות, פקודות פתוחות, מה חוסם כניסות כרגע |
| `/stop` | **עצירת חירום**: מבטל פקודות כניסה, סוגר את כל הפוזיציות במרקט ועוצר עד `/resume` |
| `/resume` | מבטל את `/stop` (לא משחרר Kill Switch ולא עצירה שבועית) |
| `/approve` | משחרר את העצירה השבועית (מינוס 5%) |
| `/reset_kill` | משחרר את ה-Kill Switch (ירידה של 10% מהשיא). השיא מתאפס להון הנוכחי |

התראות אוטומטיות: כניסה, יציאה, שגיאה, עצירות (יום/שבוע/רצף/Kill), Heartbeat כל שעה, וסיכום יומי ב-23:59.

## 5. בקטסט

```bash
python scripts/fetch_history.py --months 24   # ~2 דקות, 7 מטבעות, נרות 1m + Funding
python -m daybot.backtest                     # ~4 דקות על 4 ליבות
```

- כל סטאפ רץ **לבד** ואחר כך כולם יחד.
- חלוקה לפי זמן: 70% לבנייה, 30% מחוץ למדגם.
- לכל סטאפ מודפסים: מספר עסקאות, אחוז הצלחה, תוחלת ב-R, Profit Factor, ירידה מקסימלית, רצף הפסדים ו-P&L. אותו דבר מודפס גם עם **החלקה כפולה**.
- סטאפ שלא עבר (PF > 1.3 **מחוץ למדגם** ולפחות 300 עסקאות **מחוץ למדגם**) נכבה אוטומטית ב-`config.yaml`. התוצאות נכתבות ל-`reports/setup_gate.json`.
- **אין קובץ שער = אף סטאפ לא סוחר.**
- `--no-write` מפיק דוח בלבד, בלי לגעת בקונפיג.

איך הבקטסט מבצע:
- **כניסה:** פקודת Post-Only בסגירת נר 1m. היא מתמלאת רק אם נר מאוחר יותר **עבר** את המחיר. אם לא התמלאה תוך 3 נרות היא מבוטלת.
- **יציאה:** בתוך כל נר הסטופ נבדק ראשון. פער מעבר לסטופ מתמלא במחיר הפתיחה. ביציאה משלמים Taker + החלקה.
- **Funding:** לפי השערים האמיתיים של בינאנס.
- **פעולות ידניות:** בבקטסט הן מדומות כדי למדוד את כל התקופה. העצירה השבועית מאושרת בתחילת השבוע הבא, וה-Kill Switch משתחרר בחצות. כל הפעלה שלהם נספרת בדוח.

## 6. הרצה על VPS (Ubuntu)

```bash
# על השרת
sudo apt update && sudo apt install -y docker.io docker-compose-v2 git
sudo usermod -aG docker $USER && newgrp docker
git clone <הריפו שלך> && cd <הריפו>/daybot
cp .env.example .env && nano .env          # מפתחות Testnet + טלגרם
chmod 600 .env
mkdir -p state logs
docker compose up -d --build               # restart: always = עולה מחדש אחרי קריסה או ריבוט
docker compose logs -f                     # לראות מה קורה
```

- **נעילת IP:** במפתח ה-API בבינאנס מגבילים את הגישה לכתובת ה-IP של השרת (`curl ifconfig.me`).
  ההרשאות: **Futures בלבד, בלי משיכה (Withdraw).**
- **חלופה בלי Docker (systemd):** מעתיקים לתיקייה `/opt/daybot`, יוצרים venv ומשתמש `bot`, ואז:
  `sudo cp deploy/daybot.service /etc/systemd/system/ && sudo systemctl enable --now daybot`.
- **עדכון:** `git pull && docker compose up -d --build`.
- **הנתונים נשמרים ב-`state/`:** journal.sqlite, מצב הסיכון והעצירות.

## 7. עצירת חירום

1. **מהטלפון:** `/stop` בטלגרם. הבוט סוגר הכל ועוצר.
2. **מהשרת:** `docker compose stop`. הבוט נעצר, אבל **הסטופים והיעדים נשארים בבורסה**, כך שפוזיציה פתוחה עדיין מוגנת.
3. **אם הבוט לא עונה:** סוגרים ידנית באפליקציית בינאנס (Futures → Positions → Close All, ואז ביטול כל הפקודות).
4. **אם יש חשש לגבי המפתח:** מוחקים את מפתח ה-API בבינאנס. זה מנתק את הבוט מיד.

הדוח המלא: `reports/backtest_report.md`. בקצרה, מחוץ למדגם (מרץ–ספטמבר 2026):

| סטאפ | עסקאות | תוחלת | PF | תוצאה |
|---|---|---|---|---|
| S1 Holy Grail | 18 | +0.24R | 1.74 | נכשל: 18 עסקאות זה רעש, ובתוך המדגם הוא היה שלילי (PF 0.92) |
| S2 Turtle Soup | 4 | −0.38R | 0.21 | נכשל |
| S3 Second Entry | 489 | −0.10R | 0.62 | נכשל (שלילי מובהק) |
| S4 VWAP Reclaim | 153 | −0.13R | 0.67 | נכשל |
| S5 חוק ה-80% | 0 | — | — | נכשל (3 עסקאות בשנתיים) |

**למה זה קורה:** עלות הלוך-חזור של 0.16% דורשת סטופ של לפחות 0.8% כדי שהעלות תהיה עד 0.2R. מהלכים של 1R ומעלה ב-15m נדירים יחסית, והכניסה ב-Post-Only מתמלאת בעיקר כשהמחיר ממשיך נגדך (adverse selection).
זו אותה תוצאה שראינו בכל מחקר קודם על טווחים מתחת לשעה: אין יתרון שמכסה את העלויות.

## 9. מה צריך כדי לעבור ל-live (חלק ו')

1. לפחות סטאפ אחד שעובר את השער בבקטסט. **כרגע אין אף אחד.**
2. חודש לפחות על Testnet. כדי לאסוף מדגם על Testnet גם עם סטאפים שנכשלו, אפשר להגדיר `gate.allow_failed_on_testnet: true` ולהפעיל את הסטאפים בקונפיג. זה עובד **רק** ב-`mode: testnet`.
3. השוואה בין תוצאות ה-Testnet לבקטסט: `state/journal.sqlite`, טבלאות `trades` ו-`decisions`.
4. רק אז, ידנית: `mode: live` **וגם** `DAYBOT_LIVE_CONFIRM=I_ACCEPT_REAL_MONEY_RISK` ב-`.env`. בלי שניהם הבוט מסרב לעלות במצב live.
5. מתחילים בהון קטן.

## 10. כללים קשיחים (לא ניתנים לעקיפה מהקונפיג)

- **סיכון וגודל:** סיכון לעסקה ≤ 1% (ברירת מחדל 0.5%), מינוף ≤ 5x, Isolated, ומחיר החיסול רחוק לפחות פי 2 מהסטופ. זה נבדק גם לפני הכניסה וגם מול הבורסה אחרי המילוי.
- **מגבלות:** עד 2 פוזיציות ופקודות פתוחות, בלי שתיים באותו כיוון על מטבעות מתואמים (מתאם 1h מעל 0.7). עד 6 עסקאות ב-24 שעות.
- **עצירות:**
  - 3 הפסדים ברצף → הפסקה של 4 שעות.
  - מינוס 2% ביום → אין כניסות עד חצות.
  - מינוס 5% בשבוע → עצירה עד `/approve`.
  - מינוס 10% מהשיא → Kill Switch: סגירת הכל ועצירה.
- **חוק העלויות:** עלות מעל 0.2R (בלילה 0.15R) → אין כניסה. היעד חייב להיות לפחות 1.5R אחרי עלויות.
- **אמינות:**
  - סטופ ויעד יושבים בבורסה (STOP_MARKET / TAKE_PROFIT_MARKET, reduceOnly, לפי מחיר Mark) ומאומתים אחרי כל פקודה.
  - הזזת סטופ: קודם מניחים את החדש ורק אז מבטלים את הישן.
  - סטופ שלא אומת → הפוזיציה נסגרת. סטופ שנעלם → מוחזר, ואם זה לא מצליח → הפוזיציה נסגרת.
  - בעלייה: סנכרון מול הבורסה. פוזיציה בלי סטופ נסגרת מיד.
  - ניתוק של ה-API או נתונים ישנים (מעל 2 דקות) → אין כניסות חדשות.

## 11. מה מקורב, בכנות

- **F4** (מחזור וספרד) לא קיים בארכיון ההיסטורי. בבקטסט הוא מניח שהרשימה הקבועה נזילה. ב-live זה נבדק אמיתי.
  **ב-Testnet** הספרד והמחזור לא מייצגים את השוק האמיתי. למשל, SUI ב-Testnet מוצג עם ספרד של 0.24%, ולכן F4 יחסום אותו שם.
- **F2:** אין API חינמי ואמין ללוח אירועים. הרשימה ב-`news_events` מתוחזקת ידנית. הבוט מתריע כשאין אירוע ב-45 הימים הקרובים.
- **אישור ב-5m:** נר ה-5m האחרון סוגר בכיוון העסקה ומעבר ל-EMA20 של 5m.
- **תזמון ב-1m:** פקודת לימיט בסגירת נר 1m. ב-S3 נדרשת קודם סגירת 1m מעבר לנר הסיגנל.
- **יעדים:** סטאפ בלי יעד מבני (S3, S4, S6) מכוון ל-2R. ל-S2 שני יעדים (חצי באמצע הטווח, חצי בצד השני).
- **יציאת זמן:** 8 נרות של טיים-פריים הסטאפ בלי להגיע ל-1R. אחרי 1R יש תקרה של 32 נרות.
- **שעות:** VWAP ו-Value Area לפי יום UTC (הפתיחה היומית של בינאנס). S6 ולילה/יום לפי שעון ישראל.
- **מה נבדק בפועל:**
  - חיבור הנתונים (REST + websocket) נבדק מול ה-Testnet האמיתי: נרות, Funding, מחזור, ספרד, סגירות 1m.
  - **ביצוע פקודות אמיתי עוד לא נבדק**, כי לא היו מפתחות. הוא נבדק מול בורסה מדומה בבדיקות.
  - בהרצה הראשונה על Testnet צריך לוודא בבינאנס שהסטופ והיעד אכן מופיעים תחת Open Orders.
